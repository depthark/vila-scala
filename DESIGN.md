# Design notes

The starting point in `design-system/vila-scala/MASTER.md` was generated by the
`ui-ux-pro-max` skill for a "luxury real estate / premium residential" brief.
This file records what was taken from it, what was deliberately overridden, and
why — so the next person changing something knows which decisions are load-
bearing.

## Kept from the generated system

- **Hero-centric pattern.** One dominant hero, one primary CTA, and a visible
  cue that content continues below it.
- **Design dials** — variance 4 (balanced), motion 3 (subtle), density 3
  (spacious). The spacing scale and the 300–400 ms `power1.out`-equivalent
  easing come from those dials.
- **Its stated anti-pattern for the category:** *"poor photos + no virtual
  tours."* The virtual tour is therefore a primary action in the hero, on the
  contact page and on every apartment, not a footer link.
- **The pre-delivery checklist**, which is enforced throughout: SVG icons
  (never emoji), `cursor-pointer` on every control, 150–300 ms hover
  transitions, 4.5:1 minimum text contrast, visible focus, reduced-motion
  support, and layouts verified at 375 / 768 / 1024 / 1440.

## Deliberately overridden

**Palette.** The generated palette was a generic trust-teal + professional-blue
SaaS set (`#0F766E` / `#0369A1` on `#F0FDFA`). It has nothing to do with this
building. The palette here is taken from the building itself — warm plaster,
exposed rock, corten steel — and nothing is pure white or pure black. Every
pair was measured, not eyeballed:

| Pair | Light | Dark |
|---|---|---|
| Body text on background | 16.7:1 | 17.1:1 |
| Muted text on background | 6.6:1 | 7.5:1 |
| Accent text on background | 5.7:1 | 7.3:1 |
| Accent contrast on accent fill | 6.5:1 | 7.0:1 |
| Control border on background | 3.0:1 | 3.9:1 |

**Typography.** The generated pairing was Cinzel / Josefin Sans. Cinzel is
capitals-only, which fails on Czech sentence-case headings and reads poorly at
length. A first pass used Cormorant Garamond, but its tall, steep acutes looked
detached from ý and á at display size. Headings now use Manrope, a restrained
geometric grotesk with compact, well-seated Czech diacritics, set at weight 500
with tight tracking so the oversized display lines read as architecture rather
than ornament. Inter Variable carries the UI. Manrope's variable woff2 files
(latin + latin-ext) are downloaded from Google Fonts and self-hosted from
`src/assets/fonts/`; Inter comes from Fontsource.

**Style.** The generated style was Glassmorphism. Frosted panels would sit
badly against this photography and add blur cost for nothing. The build instead
follows the editorial / anti-grid direction that current architecture and
property sites converge on: oversized display type as the layout rather than as
decoration, tiny uppercase meta labels for exaggerated hierarchy, hairline
rules, a numbered index, controlled asymmetry, and a film grain over the whole
page. The one place glass survives is where it earns its keep — the header over
the hero, which uses `backdrop-blur` so navigation stays legible over moving
video.

## Decisions worth knowing

- **The apartments are an index, not a card grid.** Buyers compare five units on
  the same handful of figures, so those figures line up on one axis; the
  photograph appears on hover, and hovering one row dims the rest. Below `lg`
  the photo moves inline above the text, because hover does not exist there.
- **Source images live in `src/assets/`, not `public/`.** Only files that need a
  stable public URL — PDFs, the hero video, favicons, the OG image — sit in
  `public/`. Everything else goes through `astro:assets`, which is what
  produces the responsive AVIF/WebP variants; images served straight from
  `public/` get no optimisation at all.
- **The contact form opens a pre-filled e-mail** rather than posting anywhere.
  The site is fully static with no backend, and a mail client is honest about
  where the message goes. Validation, the error summary and focus management
  all run first. Swapping in a real endpoint means changing one submit handler
  in `src/scripts/app.ts`.
- **The map is OpenStreetMap, not Google Maps.** It sets no cookies, needs no
  consent banner, and lazy-loads. A direct "open in Google Maps" link sits
  beside it for anyone who wants directions.
- **There is no cookie banner** because the site sets no cookies and loads no
  third-party scripts. The only browser storage is a single `localStorage` key
  holding the visitor's theme choice, which is exempt.
